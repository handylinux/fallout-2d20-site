# Каталог-справочник: архитектура и перекрёстные ссылки

Статус: решения зафиксированы, реализация — следующими шагами.

## 1. Общая схема

- Каталог предметов и бестиарий — части одного справочника, но **отдельные
  разделы и отдельные ссылки**.
- Страницы генерируются статически из JSON и живут **вне Joomla и SPPB**.
  Joomla остаётся оболочкой: шапка, меню, форум, редакционные страницы.
- Подключение — подкаталог на том же домене (nginx/apache отдаёт статику
  раньше Joomla). `iframe` не используем.
- База данных в рантайме не нужна: источник — файлы в git, результат —
  статические страницы. БД имеет смысл только если появится несколько
  редакторов без доступа к git.
- Резолвер ссылок работает **на этапе сборки**, а не в Joomla.

## 2. Синтаксис ссылок

```
{тип:id}              → текст берётся из реестра
{тип:id|свой текст}   → текст выводится как написан
```

Примеры:

| запись | результат |
|---|---|
| `{weapon:knife}` | «Нож» → `/spravochnik/oruzhie/knife/` |
| `{weapon:knife|ножом}` | «ножом» → та же карточка |
| `{armor:leather}` | «Кожаная броня» → страница сета |
| `{armor:leather|понож}` | «понож» → страница сета |
| `{powerarmor:t45}` | «Силовая броня T-45» |
| `{creature:supermutant|супермутант}` | «супермутант» → карточка существа |
| `{term:immunity-radiation}` | термин → страница термина |

Типы (фиксированный список):

| тип | раздел |
|---|---|
| `weapon` | оружие |
| `armor` | броня |
| `powerarmor` | силовая броня |
| `ammo` | боеприпасы |
| `chem` | препараты |
| `food` | еда |
| `mod` | моды |
| `creature` | бестиарий |
| `term` | термины |
| `page` | произвольная страница Joomla |

Правила:

1. `id` — стабильный латинский слаг, не зависящий от отображаемого названия.
2. **У частей брони нет своих id.** Один id на сет: `{armor:leather}`.
   Что именно надето, пишется текстом после `|`: `{armor:leather|понож}`.
3. Текст после `|` выводится как есть: без склонений, проверок и
   автоподстановок.
4. Без `|` выводится название из реестра.
5. Неизвестный тип или id — ошибка/предупреждение сборки (режим
   настраивается), а не молчаливый текст.
6. Никаких алиасов, авто-линковки без скобок и якорей — намеренно.

## 3. Реестр

Реестр собирается из данных каталога и имеет вид:

```
(тип, id) → { title, url }
```

- Для брони запись одна на сет; части на неё только ссылаются текстом.
- Для терминов реестр дополняется словарём терминов.
- Ручных маппингов «код → замена» нет: сущность заводится один раз, все
  упоминания резолвятся автоматически.

## 4. Обработка

- Резолвер проходит по текстовым узлам готового HTML и подставляет ссылки;
  пропускает `<a>`, `<code>`, `<pre>`, `<script>`, `<style>` и атрибуты.
- Структурные поля (инвентарь, атаки, моды) хранят `тип:id` и, при
  необходимости, подпись:

  ```json
  {"type": "armor", "id": "leather", "text": "понож"}
  ```

- Из того же прохода строится граф ссылок: обратные ссылки («Встречается у»)
  и отчёт о ненайденных/неоднозначных ссылках.

## 5. Что осталось решить

- URL-префикс справочника и названия разделов (предварительно
  `/spravochnik/`).
- Строгий режим: падать на неизвестном id или только предупреждать.
- Термины без карточки: тултип, страница «Термины» или обычный текст.
