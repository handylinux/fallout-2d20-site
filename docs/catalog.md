# Каталог-справочник: архитектура и перекрёстные ссылки

Статус: решения зафиксированы, реализация — следующими шагами.

## 1. Общая схема

- Каталог предметов и бестиарий — части одного справочника, но **отдельные
  разделы и отдельные ссылки**.
- Страницы генерируются статически из JSON и живут **вне Joomla и SPPB**.
  Joomla остаётся оболочкой: шапка, меню, форум, редакционные страницы.
- Подключение — подкаталог на том же домене (nginx/apache отдаёт статику
  раньше Joomla). `iframe` не используем.
- База данных в рантайме не нужна: источник — файлы в git, результат —
  статические страницы. БД имеет смысл только если появится несколько
  редакторов без доступа к git.
- Резолвер ссылок работает **на этапе сборки**, а не в Joomla.

## 2. Синтаксис ссылок

```
{тип:id}              → текст берётся из реестра
{тип:id|свой текст}   → текст выводится как написан
```

Примеры:

| запись | результат |
|---|---|
| `{weapon:knife}` | «Нож» → `/spravochnik/oruzhie/knife/` |
| `{weapon:knife|ножом}` | «ножом» → та же карточка |
| `{armor:leather}` | «Кожаная броня» → страница сета |
| `{armor:leather|понож}` | «понож» → страница сета |
| `{powerarmor:t45}` | «Силовая броня T-45» |
| `{creature:supermutant|супермутант}` | «супермутант» → карточка существа |
| `{spec:fly}` | «**Полёт** — существо может летать…» (текст, не ссылка) |

Типы (фиксированный список):

| тип | раздел |
|---|---|
| `weapon` | оружие |
| `armor` | броня |
| `powerarmor` | силовая броня |
| `ammo` | боеприпасы |
| `chem` | препараты |
| `food` | еда |
| `mod` | моды |
| `creature` | бестиарий |
| `spec` | особенности существ (встраиваемый текст) |
| `page` | произвольная страница Joomla |

Тип `term` не нужен: термины и правила пока описываются через `spec`
(встраиваемый текст) или `page` (если понадобится отдельная статья Joomla).

Правила:

1. `id` — стабильный латинский слаг, не зависящий от отображаемого названия.
2. **У частей брони нет своих id.** Один id на сет: `{armor:leather}`.
   Что именно надето, пишется текстом после `|`: `{armor:leather|понож}`.
3. Текст после `|` выводится как есть: без склонений, проверок и
   автоподстановок.
4. Без `|` выводится название из реестра.
5. Неизвестный тип или id — ошибка/предупреждение сборки (режим
   настраивается), а не молчаливый текст.
6. Никаких алиасов, авто-линковки без скобок и якорей — намеренно.

## 3. Встраиваемые статьи: `spec`

Особенности существ — не отдельные страницы, а статьи справочника, которые
подставляются прямо в текст:

```
{spec:fly}
{spec:immunity-radiation}
```

Превращается в:

```html
<strong>Полёт</strong> — Существо может летать…
```

- Название и описание берутся из справочника особенностей.
- `|` переопределяет **только название**: `{spec:fly|полёт}` →
  «**полёт** — Существо может летать…».
- Ссылки и обратных ссылок у `spec` нет: это текст, а не сущность каталога.
- HTML описания вставляется как есть, но на сборке чистится от скриптов,
  обработчиков событий и опасных тегов.
- Вложенные `{...}` внутри описания на первом этапе запрещены — сборка
  сообщает об этом в отчёте (защита от рекурсии).
- Неизвестный `spec:id` — ошибка/предупреждение сборки, как и для остальных
  типов.
- Тот же inline-режим позже используется для качеств оружия и эффектов
  (`{quality:...}`, `{effect:...}`), когда будет их дизайн.

## 4. Реестр

Реестр собирается из данных каталога и имеет вид:

```
(тип, id) → { title, url }
```

- Для брони запись одна на сет; части на неё только ссылаются текстом.
- Для `spec` запись содержит `title` и `text`, без `url`: у этих статей нет
  собственных страниц.
- Ручных маппингов «код → замена» нет: сущность заводится один раз, все
  упоминания резолвятся автоматически.

## 5. Обработка

- Резолвер проходит по текстовым узлам готового HTML; пропускает `<a>`,
  `<code>`, `<pre>`, `<script>`, `<style>` и атрибуты.
- Два режима по типу: `link` — подставляет `<a href>`, `inline` (`spec`) —
  вставляет размеченный текст.
- **Мягкий режим по умолчанию.** Неизвестный или кривой шорткод не роняет
  сборку: он остаётся в тексте как есть (`{spec:flly}`), а в отчёт попадает
  страница, файл и само место ошибки. Так опечатку видно и на странице, и в
  логе, и её можно исправить вручную.

  ```text
  build-report.txt
  pages/supermutant.html: {spec:flly} — неизвестный id (spec)
  ```

  Строгий режим (`--strict`) остаётся опцией для CI, но не поведением по
  умолчанию.
- Структурные поля (инвентарь, атаки, моды) хранят `тип:id` и, при
  необходимости, подпись:

  ```json
  {"type": "armor", "id": "leather", "text": "понож"}
  ```

- Из того же прохода строится граф ссылок: обратные ссылки («Встречается у»)
  и отчёт о ненайденных/неоднозначных ссылках.

## 6. Будущие типы

- `quality` — качества оружия, `effect` — эффекты. Данные (по крайней мере
  списки) есть в Companion; в нашей копии пока только эффекты брони, остальное
  синхронизируем при подключении.
- Режим вывода (inline-текст или ссылка) решим, когда будет дизайн. Тултипы
  отложены: их дизайн будет отдельным и привязан к эффектам и качествам.

## 7. Что осталось решить

- URL-префикс справочника и названия разделов (предварительно
  `/spravochnik/`).
- Нужен ли `--strict` в CI (по умолчанию — мягкий режим).
