# PDF-справочник оружия: шаблон A4

Одна единица оружия — одна страница A4. Макет снят с PDF, собранного в
Publisher (`docs/render/Справочник оружия-pinkibook-018.pdf`, страница 18,
«Боевой карабин»), и воспроизводится скриптом `tools/weapon2pdf.py`.

```
JSON карточки  →  tools/weapon2pdf.py  →  PDF (A4, одна страница)
```

Карточка — это уже готовые к печати данные (заголовок, статы, описание,
строки модификаций). Отдельный слой «Companion JSON → карточка» появится
следующим шагом: один и тот же JSON потом будет питать и веб-каталог.

## Цвета

| Что | RGB | HEX |
|---|---|---|
| Бумага | фон-текстура из PDF | ≈ #F2F1EF |
| Бежевые ячейки | 255, 235, 205 | `#FFEBCD` |
| Оранжевые ячейки | 255, 198, 116 | `#FFC674` |

Фон — та же бумажная текстура, что в PDF (`assets/pdf/paper.jpg`), растянута

## Шрифты

В оригинале — **Calibri** и **Calibri Bold** (подтверждено `pdffonts`).
В генераторе — **Carlito** (`assets/fonts/`, лицензия OFL): метрически
совместимый свободный клон Calibri, поэтому переносы и ширина строк
совпадают с оригиналом. Кегли:

* заголовок 21.98 pt Bold, капс;
* подзаголовок 14.04 pt;
* шапка таблицы 9.96 pt Bold, «СКОРОСТЬ СТРЕЛЬБЫ» — 9 pt в две строки;
* ячейки статов 9.96 pt;
* описание 12 pt, интерлиньяж 17.4 pt, выключка по ширине;
* заголовок «ПОДДЕРЖИВАЕМЫЕ МОДИФИКАЦИИ» 18 pt Bold;
* моды 9 pt, интерлиньяж 13.08 pt;
* метки слотов 9.96 pt Bold, белые.

## Правила таблицы модификаций

* Слотов максимум 6 колонок; в строке — до 6 модов.
* Если у категории больше 6 модов, она занимает несколько строк по 6 ячеек;
  чёрная метка слота растягивается на весь блок и центрируется по вертикали.
* Цвет блока чередуется: бежевый → оранжевый → бежевый …
* Пустые ячейки остаются в сетке и заливаются цветом блока.
* Таблица растягивается до нижнего поля: свободное место делится поровну
  между строками, но не больше ~47 pt на строку (иначе одна категория
  превратилась бы в гигантскую строку). Если строк мало, таблица просто
  заканчивается выше.
* Если модов нет вообще — вместо таблицы выводится
  «НЕТ ПОДДЕРЖИВАЕМЫХ МОДИФИКАЦИЙ».
* Порядок категорий: РЕСИВЕР, СТВОЛ, РУКОЯТЬ, ЛОЖА, МАГАЗИН, ПРИЦЕЛ, ДУЛО
  (как в присланных страницах).

## Нумерация

Номер страницы стоит в наружном поле: чётные страницы — слева, нечётные —
справа (в PDF страница 18 — слева, на скриншоте страница 15 — справа).

## Что делать с длинным описанием

Область описания — примерно 4 строки при 12 pt. Если текст не влезает,
кегль уменьшается до 10 pt (интерлиньяж — пропорционально). Если и этого
мало, текст обрезается по границе слова с «…» и выводится предупреждение:
лучше поправить текст руками, чем молча получить наложение на таблицу.

## Данные Companion

Что уже есть в `data/companion/`:

| Поле PDF | Источник |
|---|---|
| Название | `ru-RU/.../weapons/weapons.json` → `name` |
| Вес / Цена / Редкость | `weapons.json` → `weight`, `cost`, `rarity` |
| ПАТРОН | `ammoId` → `ammo/ammo_types.json` |
| ТИП УРОНА | `damageType` |
| УРОН | `damage` + иконка `assets/pdf/damage-icon.png` |
| СКОРОСТЬ СТРЕЛЬБЫ | `fireRate` |
| ДИСТАНЦИЯ | `range` → `rangeName` из RU-файла |
| ЭФФЕКТЫ | `effects[]` → `ru-RU/data/system/damageEffects.json` |
| КАЧЕСТВА | `qualities[]` → `ru-RU/data/system/qualities.json` |
| Моды | `weapon_mod_slots.json` + `weapon_mods.json` (RU) |
| Описание | **нет русского** (см. ниже) |
| Картинка | **нет в данных** |

Русские названия эффектов лежат в `damageEffects.json` (10 записей,
`effect_vicious` → «Порочный»), качества — в `qualities.json`
(`quality_close_quarters` → «Вплотную»).

### Чего не хватает

1. **Описания.** В RU-файле 130 из 146 `flavour` — английские, 5 пустых.
   Русские тексты компонуются вручную; генератору нужен файл
   `data/weapons/descriptions.ru.json` (`id → текст`).
2. **Картинки.** В Companion их нет. Ожидаемый путь —
   `assets/pdf/weapons/<slug>.png`, PNG с прозрачностью.
3. **Иконка урона.** В PDF она 41 × 41 px, для печати это мало
   (20 pt при 300 dpi ≈ 83 px). Нужен исходник в 2×.
4. **Порядок модов.** В PDF он не совпадает с порядком данных Companion
   (похоже, ручной, «как в книге»). Нужно правило: данные, алфавит или
   ручные списки на оружие.
5. **Слоты роботов.** В данных встречаются `Unique`, `Capacitor`, `Nozzle`,
   `Frame`, `Winch`, `Dish`, `Tank`, `Fuel`, `Launcher`, `Canister`,
   `Concentrate`, `Container`, `Camera` — для них пока нет русских меток
   и не определено поведение при > 6 категориях.
6. **Типы урона.** В данных: `physical`, `energy`, `["energy","physical"]`,
   `radiation`, `special`, `poison`. Нужны точные русские подписи для
   составных и редких типов.

## Отличия от Publisher-оригинала

* Заголовок, линейка и подзаголовок центрированы по полю контента; в PDF
  они смещены вправо на ~13–18 pt (ручная погрешность вёрстки).
* Картинка вписывается с сохранением пропорций; в PDF она растянута по
  вертикали примерно на 16 %.
* Высота строк модов считается по содержимому и выравнивается до нижнего
  поля; в оригинале строки местами раздуты вручную (строка «ПРИЦЕЛ»
  на странице 18 выше остальных).

## Запуск

```bash
python3 -m pip install -r tools/requirements-pdf.txt
python3 tools/weapon2pdf.py data/weapons/cards/combat-rifle.json \
    --out docs/render/out/combat-rifle.pdf
```

Проверка:

```bash
python3 -m unittest discover -s tools -v
```

`docs/render/out/` — черновики, в git не попадают.
