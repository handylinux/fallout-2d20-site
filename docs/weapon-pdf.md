# PDF-справочник оружия: шаблон A4

Одна единица оружия — одна страница A4. Макет снят с PDF, собранного в
Publisher (`docs/render/Справочник оружия-pinkibook-018.pdf`, страница 18,
«Боевой карабин»), и воспроизводится скриптом `tools/weapon2pdf.py`.

```
Companion JSON  →  tools/weapons2cards.py  →  карточка JSON
                                            →  tools/weapon2pdf.py  →  PDF A4
```

Карточка — это уже готовые к печати данные (заголовок, статы, описание,
строки модификаций). Тот же JSON потом будет питать и веб-каталог.

## Правила таблицы модификаций

* Число колонок под моды равно самому большому количеству модов в категории
  (но не больше 6): один мод — одна колонка на всю ширину, три мода — три
  колонки, восемь — две строки по шесть. Колонка метки (36.61–86.54 pt)
  всегда одна и та же, остальные колонки делят ширину до 559.28 pt поровну.
* Если у категории больше 6 модов, она занимает несколько строк по 6 ячеек;
  чёрная метка слота растягивается на весь блок и центрируется по вертикали.
* Цвет блока чередуется: бежевый → оранжевый → бежевый …
* Пустые ячейки остаются в сетке и заливаются цветом блока.
* Высота строки зависит только от содержимого (одна строка текста —
  20.73 pt, две — 31 pt, три — 43.5 pt) и не растягивается.
* Таблица строится от нижней границы вверх: низ таблицы всегда на 803.35 pt,
  верх — настолько выше, насколько хватает строк. Поэтому у оружия с одним
  модом под заголовком остаётся пустое место, зато таблица не раздувается.
* Заголовок «ПОДДЕРЖИВАЕМЫЕ МОДИФИКАЦИИ» стоит в 45.36 pt над таблицей:
  при полной таблице он оказывается на книжном месте (488.29), у короткой
  таблицы опускается вместе с ней, чтобы не оставалось дыры.
* Если строки не помещаются в отведённую высоту (533.65–803.35), они
  сжимаются пропорционально и печатается предупреждение.
* Если модов нет вообще — вместо заголовка выводится одна строка
  «НЕТ ПОДДЕРЖИВАЕМЫХ МОДИФИКАЦИЙ» (18 pt Bold).
* Длинные значения в таблице статов (например, «Энергетический» или
  «Крио-элемент») автоматически уменьшаются до 2 строк, чтобы не вылезать
  в соседнюю ячейку.
* То же и для модов: если одно слово шире ячейки (например,
  «Квантовая гиростабилизирующая линза»), кегль этой ячейки уменьшается
  с 9 pt до 6.5 pt, переносы остаются по словам.
* Эффекты печатаются через запятую в том порядке, что в данных; значение
  (например, `effect_piercing_x` с `value: 2`) выводится как
  «Проникающий 2». Три эффекта в узкой ячейке («Порочный, Разрушающий,
  Радиоактивный» у «Толстяка») уменьшаются до 2 строк.
* Набор категорий у каждого оружия свой: берутся только те слоты, что есть
  в `weapon_mod_slots.json`. Порядок: РЕСИВЕР, СТВОЛ, КОНДЕНСАТОР, СОПЛО,
  РУКОЯТЬ, ЛОЖА, МАГАЗИН, ПРИЦЕЛ, ДУЛО, затем остальные по алфавиту (как в
  присланных страницах). Моды внутри категории — в порядке данных Companion.
* Русские метки слотов лежат в Companion
  (`i18n/ru-RU/screens-weaponsAndArmor.json` → `weapon.modSlots` — копия
  `screens/weaponsAndArmor/screen.json` из компаньона,
  21 ключ: `receiver`, `barrel`, `sight`, `muzzle`, `stock`, `grip`,
  `magazine`, `capacitor`, `canister`, `concentrate`, `container`, `dishe`,
  `fuel`, `launcher`, `nozzle`, `tank`, `frame`, `winch`, `chamber`,
  `unique`, `other`). Для семи классических слотов оставлены книжные
  написания (ДУЛО, ЛОЖА, …), остальные печатаются капсом из перевода
  (КОНДЕНСАТОР, СОПЛО, …). Написания в данных расходятся с ключами перевода
  для `Dish` → «Диск» и `Camera` → «Камера» — для них есть алиасы.
* Уникальные моды оружия — не отдельный тип данных: в Companion они лежат в
  `weapon_mods.json` со слотом `Unique` и перечислены в
  `weapon_mod_slots.json` у конкретного оружия (все 66 связей «мод → оружие»
  присутствуют в слотах, ничего не теряется). В PDF они идут строкой
  «УНИКАЛЬНЫЙ» в общем блоке модов.

## Нумерация

Номер страницы стоит в наружном поле: чётные страницы — слева, нечётные —
справа (в PDF страница 18 — слева, на скриншоте страница 15 — справа).

## Что делать с длинным описанием

Описание занимает всё место над блоком модов: нижняя граница считается от
верха таблицы (45.36 pt на заголовок и 10 pt отступа). Чем короче таблица,
тем больше строк доступно — на страницах с 4–5 строками модов это 12–18
строк описания вместо прежних четырёх.

На карточке без таблицы модов уведомление «НЕТ ПОДДЕРЖИВАЕМЫХ
МОДИФИКАЦИЙ» при необходимости сдвигается ниже полного описания; короткие
тексты остаются на исходной позиции. Если текст не помещается даже после
уменьшения кегля до 10 pt, сборка завершается с `ValueError`. Описание
никогда не обрезается многоточием и не накладывается на заголовок или
таблицу.

### Чего не хватает

1. **Описания.** В RU-файле 130 из 146 `flavour` — английские, 5 пустых.
   Пока это устраивает: генератор берёт `flavour` как есть. Когда появятся
   русские тексты, их достаточно положить в
   `data/weapons/descriptions.ru.json` (`id → текст`) — скрипт подхватит
   автоматически.
2. **Картинки.** В Companion их нет. Ожидаемый путь —
   `assets/pdf/weapons/<slug>.png`, PNG с прозрачностью. Для примеров
   подставляется `assets/pdf/weapons/combat-rifle.png` (заглушка).
   Арт берём из книги: `python3 tools/extract_pdf_images.py книга.pdf
   --out art/` вытаскивает все встроенные изображения, отбрасывает текстуру
   бумаги (картинка во всю страницу) и мелочь, кладёт `index.html` с номерами
   страниц и `report.csv`. Имена файлов — по заголовку страницы: скрипт
   читает самую крупную надпись сверху, нормализует регистр и «ё», находит
   её в `weapons.json` и берёт слаг из id (`combat-rifle.png`), так что файл
   сразу ложится в `assets/pdf/weapons/`. Нераспознанные страницы остаются
   `p018.png` с пустым `weapon_id` в CSV.
   Картинки в книге уже с альфа-каналом (SMask) и примерно 1100–2600 px
   по длинной стороне — этого хватает на 300 dpi.
3. **Иконка урона.** Та же `CD.png`, что на сайте; в PDF она 41 × 41 px
   (для 20 pt при 300 dpi хотелось бы ~83 px, но пока печатается как есть).
4. **Слоты роботов.** Роботов пока не трогаем: в книге только оружие.
   Метки для всех 21 слота уже подтягиваются из
   `screens/weaponsAndArmor/screen.json`, поэтому энергооружие
   («Конденсатор», «Сопло») и прочие типы собираются без правок кода.
5. **Типы урона.** Русские подписи уже есть в Companion
   (`addItemModal.json`): Физический, Энергетический, Радиационный, Особый,
   Яд. Для составного `["energy","physical"]` склеиваем через «и».

## Отличия от Publisher-оригинала

* Заголовок, линейка и подзаголовок центрированы по полю контента; в PDF
  они смещены вправо на ~13–18 pt (ручная погрешность вёрстки).
* Картинка растягивается по рамке (как в PDF). Искажение пропорций —
  намеренное: так все стволы занимают одинаковое место на странице.
* Высота строк модов считается по содержимому: строка выше, если название
  мода занимает 2–3 строки. Свободное место до нижнего поля делится между
  строками, поэтому таблица всегда заканчивается на 803.35 pt.

## Художественный слой из Publisher

Обычный режим вставляет `card.image` в стандартный `IMAGE_BOX`. Для
контрольной пересборки Publisher-страницы используйте манифест, созданный
`tools/extract_pdf_images.py`. Опция `--artwork-manifest` выбирает страницу
сначала по `weapon_id` и идентификатору карточки, затем по номеру `page`.
`--artwork-page N` нужен только для ручного выбора.

```bash
# 1. PNG + artwork-manifest.json из исходного Publisher PDF
python3 tools/extract_pdf_images.py "Справочник оружия.pdf" \
    --out docs/render/pdf-extract/publisher-art --min-size 300

# 2. Векторный текст и таблицы — от генератора, иллюстрации — из manifest
python3 tools/weapon2pdf.py data/weapons/cards/combat-rifle.json \
    --out docs/render/out/combat-rifle-manifest.pdf \
    --artwork-manifest docs/render/pdf-extract/publisher-art/artwork-manifest.json
```

Рендерер не пересчитывает положение рисунка из видимого bbox: он применяет
исходную `matrix_pdf` к единичному изображению, все `clip_paths`, `fill_alpha`
и blend mode в исходном `draw_order`. Размер страницы также берётся из
`size_points` манифеста, поэтому Publisher A4 595.32×841.92 pt не округляется
до номинального ReportLab A4. Каждый placement рисуется отдельно: повторное
использование одного PNG и частично видимое изображение с соседней страницы
сохраняются.

Image `/SMask` уже запечён в экспортированном RGBA PNG и передаётся ReportLab
через `mask="auto"`. В schema v1 отдельный ExtGState `/SMask` хранится только
как xref без pixel payload; такой случай рендерер намеренно останавливает с
понятной ошибкой, а не подменяет эффект. В проверенном Publisher-исходнике
художественные placement используют image SMask и unit ExtGState alpha.

## Полный русский каталог оружия

`tools/build_weapon_catalog.py` собирает `book-weapon-catalog.pdf` из
редактируемых данных и исходного Publisher PDF. В книге 176 страниц (кратно
4), печатное оглавление занимает страницы 4–5, а 144 карточки распределены
по стрелковому, тяжёлому, энергетическому, ближнему, рукопашному,
метательному оружию и взрывчатке. Заголовки, таблицы и описания генерируются
из `data/weapon-book/companion/` и override-файлов `data/weapons/`; не нужно
ручным способом править сотни неоднородных Publisher-таблиц. Таблицы общих
модификаций идут после разделителей своих глав, а дополнительная таблица и
карточка оружия Института входят в главу энергетического оружия. Печатное
оглавление и PDF-закладки используют одну карту страниц. «Рукопашная
атака» включена отдельной карточкой. «Голова ассаултрона» и «Опасная бритва»
не являются самостоятельным оружием и не включаются; отдельная карточка
«Головной лазер Штурмотрона» сохранена.

Для полной книги действует более строгий режим, чем для единичной карточки:
`tools/weapon_catalog_artwork.py` разрешает слой art **только** при точном
совпадении `weapon_id` с manifest. Номер страницы уже собранной книги не
является fallback, потому что после вставки оглавления он больше не совпадает
с номером исходника. Manifest содержит SHA-256 Publisher PDF, который
сверяется перед сборкой; отсутствующий asset или несовместимый графический
state прекращают сборку с ошибкой. Отчёт coverage фиксирует для каждой
карточки либо source page/xref/asset, либо честный статус отсутствия art.
У `weapon_institute_laser` в этом Publisher manifest нет exact-ID страницы:
карточка намеренно публикуется пустой (`no-manifest-page`), без заимствования
рисунка `weapon_laser_gun`.

Для опубликованной версии после вёрстки используется `--rasterize-cover`:
только первая страница заменяется одним непрозрачным RGB JPEG 300 DPI с
quality 92. Это фиксирует все слои исходной Publisher-обложки в её финальном
виде; остальные 175 страниц canonical PDF остаются векторными/слойными.

```bash
# 1. Снять manifest и RGBA artwork именно с используемого Publisher PDF.
python3 tools/extract_pdf_images.py "Справочник оружия.pdf" \
  --out docs/render/pdf-extract/publisher-art --min-size 300

# 2. Собрать и опубликовать итоговый PDF и его компактную карту provenance.
python3 tools/build_weapon_catalog.py "Справочник оружия.pdf" \
  --out docs/render/samples/book-weapon-catalog.pdf \
  --report docs/render/out/book-weapon-catalog-report.md \
  --artwork-manifest docs/render/pdf-extract/publisher-art/artwork-manifest.json \
  --artwork-root docs/render/pdf-extract/publisher-art \
  --artwork-coverage docs/render/samples/book-weapon-catalog-artwork-coverage.json \
  --rasterize-cover --cover-dpi 300 --cover-jpeg-quality 92
```

В проверенной сборке 77 карточек используют точные размещения Publisher; у
шести исходных страниц не оказалось экспортируемого raster placement, а у 61
добавленной или не представленной в исходнике карточки нет manifest page.
Эти 67 карточек остаются без иллюстрации, а не получают artwork другого
оружия. В частности, контроль страницы 24 (`weapon_double_barrel_shotgun`,
xref 468) подтверждает точные matrix `[434.73, -85.906, 62.688, 317.24,
36.9, 520.84]`, custom crop и `/SMask` в готовой книге.

### Резервная мобильная растровая версия

`book-weapon-catalog.pdf` остаётся канонической печатной версией: после
сведения JPG-обложки в ней сохранены отдельные RGBA иллюстрации, Publisher
affine matrix, crop и alpha на остальных страницах. Если определённый мобильный
viewer ошибочно композитит эти PDF-слои, из
готового канонического файла создаётся отдельный
`book-weapon-catalog-mobile-raster.pdf`:

```bash
python3 tools/rasterize_pdf.py docs/render/samples/book-weapon-catalog.pdf \
  --out docs/render/samples/book-weapon-catalog-mobile-raster.pdf \
  --dpi 200 --jpeg-quality 85
```

Это **не** непрозрачная подмена PNG оружия. Скрипт использует нормальный PDF
renderer для всей страницы, так что прозрачный artwork уже скомпонован с её
фоном после применения исходной matrix/crop/alpha. Затем он записывает один
непрозрачный RGB JPEG на страницу. В результате мобильный файл не содержит
текстовых блоков, шрифтов, векторных объектов, `/SMask` или отдельных
трансформируемых artwork-слоёв — только 176 цельных растровых страниц.
`assert_raster_only()` проверяет этот контракт перед атомарной публикацией
файла. Цена совместимости: текст нельзя искать или выделять, а для печати
нужно выбирать основную векторную версию.

## Запуск

```bash
python3 -m pip install -r tools/requirements-pdf.txt
python3 tools/weapon2pdf.py data/weapons/cards/combat-rifle.json \
    --out docs/render/out/combat-rifle.pdf
```

Проверка:

```bash
python3 -m unittest discover -s tools -v
```

`docs/render/out/` — черновики, в git не попадают. Готовые образцы лежат в
`docs/render/samples/` (там же README со списком страниц).
