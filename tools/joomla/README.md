# Массовое создание страниц в Joomla из JSON

Скрипты в этой папке делают то, из-за чего всё затевалось: **не нужно руками
заводить страницу на каждое оружие**. Данные берутся из `data/source/*.json`,
а Joomla получает готовые записи.

Работает без подключения к вашей базе. Скрипты только **генерируют файлы** —
что и когда импортировать, решаете вы.

---

## Быстрый старт

```bash
# 1. Посмотреть, что вообще есть в данных и что будет создано
python3 tools/joomla/generate_joomla_full.py --source weapons --dry-run

# 2. Сгенерировать превью HTML (без Joomla!) — проверить глазами
python3 tools/joomla/generate_joomla_pages.py --mode html --out /tmp/preview
#    открыть /tmp/preview/index.html

# 3. Сгенерировать SQL для Joomla
python3 tools/joomla/generate_joomla_full.py \
    --source weapons \
    --out joomla_weapons.sql \
    --catid 18 \
    --parent-menu 269 \
    --parent-alias snaryazhenie \
    --start-id 10000
```

На выходе:

| Файл | Что внутри |
|---|---|
| `joomla_weapons.sql` | INSERT-ы в `jos_content`, `jos_sppagebuilder`, `jos_menu` |
| `joomla_weapons.sql.report.json` | карта: id статьи → название → alias |

---

## Что создаётся на каждую единицу контента

В Joomla одна страница — это **три** записи, связанные между собой. Если
сделать только раскладку SPPB, страница не появится:

```
jos_content.id = 10000  ← сама статья (заголовок, alias, текст, категория)
        ↑
        │ view_id
jos_sppagebuilder.id = 10000  ← визуальная раскладка (таблица статов, картинка)
        ↑
        │ link = index.php?...&id=10000
jos_menu.id = 10000  ← пункт меню (без него нет ЧПУ-адреса)
```

Именно так это устроено в вашей выгрузке: `jos_sppagebuilder.view_id`
указывает на `jos_content.id`.

## Параметры, которые надо сверить со своей базой

Скрипт не угадывает ваши id — их надо задать. Проверить можно так:

```sql
-- id категории, куда складывать оружие
SELECT id, title, parent_id FROM jos_categories WHERE extension = 'com_content';

-- родительский пункт меню (если страницы идут вложенным списком)
SELECT id, title, alias FROM jos_menu WHERE menutype = 'mainmenu';

-- component_id для com_content
SELECT extension_id FROM jos_extensions WHERE element = 'com_content';
```

По умолчанию: `--catid 18`, `--component-id 22`, `--start-id 10000`.
**id статей начинаются с 10000 специально**, чтобы не перезаписать существующие.

## Порядок импорта (безопасный)

1. **Бэкап.** `mysqldump -u USER -p БАЗА > backup_$(date +%F).sql`
2. **Копия базы.** Прогнать SQL на копии (локально/docker), не на живой.
3. **Проверить 1–2 адреса** на копии: открывается ли страница, видна ли
   таблица, работает ли пункт меню.
4. **Импорт на живой:**
   ```bash
   mysql -u USER -p БАЗА < joomla_weapons.sql
   ```
5. **Сбросить кэш Joomla** (Система → Очистка кэша) и проверить адреса.

Если что-то пошло не так — откат: удалить записи с id >= 10000
(`DELETE FROM jos_content WHERE id >= 10000;` и так же для двух других таблиц)
или восстановить из бэкапа.

## Честно о состоянии данных

Скрипт предупреждает об этом перед генерацией:

| Проблема | Сколько | Что делать |
|---|---|---|
| Описание на английском | **127 из 146** | `--skip-english-desc` убрать их, либо перевести |
| Без описания | 5 | останутся только статы |
| Без картинки | 2 | добавить `imageName` в `weapons.json` |
| Без дистанции | 47 | это ближний бой/взрывчатка — норма |

127 английских описаний — главная незакрытая часть. Это не баг скрипта:
в `data/source/weapons.ru.json` лежит английский `flavour` (видимо, из
английского оригинала). Варианты:

- `--skip-english-desc` — публикуем без описаний, только статы (быстро);
- перевести 127 текстов и положить обратно в `weapons.ru.json` (качественно);
- оставить как есть, если английские описания устраивают (тогда не флаг).

## Файлы

| Скрипт | Назначение |
|---|---|
| `generate_joomla_pages.py` | Только раскладки SPPB. Режимы: `--mode html` (превью), `--mode json` (по файлу на страницу), `--mode sql`, `--mode list` |
| `generate_joomla_full.py` | Полный пакет: статья + раскладка + пункт меню, со связкой id и валидацией |

Оба используют **эталонную страницу** «Боевой карабин» из выгрузки SPPB как
шаблон вёрстки — то есть структура таблицы и оформление берутся с уже
существующей страницы сайта, а не придумываются.

Требуются выгрузки (пути можно переопределить переменными окружения):
`SPPB_DUMP` → `jos_sppagebuilder.json`, `CONTENT_DUMP` → `jos_content.json`.

## Что дальше (если понадобится)

Скрипт легко расширяется на другие типы контента — структура та же:

- **мобы** — `data/source/` пока без них; нужен аналогичный JSON
  (имя, HP, урон, способности) и страница-шаблон из выгрузки SPPB;
- **моды оружия** — `weapon_mods.json` + `weapon_mods.ru.json` уже есть (164 шт.);
- **броня** — `armor_detail.json`, `armor_mods.json` (12 шт.);
- **патроны** — `ammo.ru.json` (51 шт.);
- **качества** — `qualities.ru.json` (32 шт.).

Для каждого типа нужен свой список колонок таблицы — он снимается с любой
реальной страницы этого типа тем же способом, что и для оружия.
